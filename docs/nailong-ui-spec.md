## 2. 视觉基调：从"奶龙"里提取什么

参考对象是《奶龙》（第七印象）的**风格语言**，不是照搬角色形象。提取出四条可工程化的特征：

1. **明亮温暖的黄色为主体色**——不是糖果荧光黄，是偏奶油/蛋黄的低饱和暖黄。
2. **一切皆圆润**——圆脑袋、胖身材的造型语言，投射到界面就是"没有直角"：卡片 20–28px 圆角，标签全用胶囊。
3. **黑亮圆眼 + 两朵红晕**——这是奶龙最可识别的面部特征，成为吉祥物的核心元素。
4. **温暖治愈而非冷硬**——用暖深棕替代纯黑做文字色，阴影带暖调，遮罩不发灰。

### 关于角色形象的处理方式（重要）

吉祥物 **「小记龙」是本次原创的**，只借鉴风格特征，不复制奶龙的具体形象：

- 采用纯 CSS 几何绘制（`<view>` + `border-radius` + 渐变 + 内阴影），**不引入任何图片/SVG 资源**。
  好处是：APK 体积零增长；H5 / App / 未来小程序三端通用（小程序不支持内联 `<svg>`）。
- 只做**头像式**（仅头部），不做全身：46px 的下限尺寸下，全身造型会糊成一团，只留头部才能保持清晰。
- 与真实 IP 的差异是刻意保留的：奶龙无耳朵、有长尾巴与短爪，本吉祥物改用一撮"呆毛"区分，避免与商业 IP 形象混淆（若将来公开发布，也不存在形象侵权风险）。
- 两个表情状态：`happy`（默认，用于记一笔金额区、我的页）/ `sleep`（眯眼打盹 + 浮动 + "z"，仅用于明细空状态）。

### 3.2 为什么保留 #e24b4a / #12924f（而不是一起调暖）

这两个是**语义色**，不是装饰色：红支绿收是 PRD §8 冻结的产品规范，用户对金额方向的识别依赖它。
把它们调成暖色会削弱语义、且违反已冻结的文档。因此本次只换"氛围色"（底、容器、主色），**语义色原样保留**。

### 3.3 语义色的使用规则（本次新增的可访问性约束）

金额红绿在**白底**上的对比度是 3.94:1 / 4.00:1——达到 WCAG AA 的**大字号**门槛（≥3:1），但达不到正文字号的 4.5:1。
因此定死一条规则：

> **红 / 绿只出现在金额数字上，且金额一律 ≥19px 粗体。**

推论：
- 记一笔大金额 30px、明细条目金额 19px、月合计 19px —— 全部命中"大字号"档。
- 「支出 / 收入」这类小字标签一律用 `--cd-ink` / `--cd-ink-2`，不用红绿（分段控件的选中态改用品牌黄底 + 深棕字）。
- 唯一的红色小字场景（删除按钮）走加深档 `--cd-danger-ink`，对 `--cd-danger-lt` 为 4.90:1，满足正文 4.5:1。

### 3.4 分类图标底色

`src/utils/palette.js` 提供 8 个柔和底色，按**分类 id**（不是数组下标）循环取色：

```
#fff0be 奶黄 · #e6f6ff 天空蓝 · #ffedf0 腮红粉 · #e8f8f0 薄荷绿
#fff1e3 奶油橙 · #ede9ff 淡紫 · #e4f5f7 淡青 · #fbeaf2 淡玫
```

内置分类 id 为 1..12（8 支出 + 4 收入），8 色一循环后：**支出 8 项颜色两两不同，收入 4 项也两两不同**。
按 id 取色（而非按位置）是为了让同一分类在宫格、明细列表、编辑弹层 chip 三处颜色完全一致。

## 4. 一致性原则

### 4.1 圆角

| 令牌 | 值 | 用途 |
|---|---|---|
| `--cd-r-pill` | 999px | 标签、chip、把手 |
| `--cd-r-lg` | 28px | 卡片、弹层顶角 |
| `--cd-r-md` | 20px | 按钮、输入框、分组卡、金额卡 |
| `--cd-r-sm` | 16px | 键盘键、分段控件内块 |

规则：**界面内不出现直角**；同类元素必须用同一个令牌，不允许"这里 10px 那里 12px"。

### 4.2 字体

- **不打包字体文件**（避免 APK 体积与首屏成本），使用系统圆体栈：
  `MiSans → HarmonyOS Sans SC → PingFang SC → Noto Sans SC → system-ui`
  测试机 Xiaomi 14 Pro / HyperOS 命中 **MiSans**，本身即圆润几何无衬线，天然贴合本风格。
- 字号档位：11 / 12 / 13 / 14 / 15 / 16 / 17 / 19 / 21 / 30px。
- 字重只用 400 / 600 / 700；标题与数字一律 700，避免"胖乎乎"的圆润造型配细字重。
- **所有金额数字**加 `font-variant-numeric: tabular-nums`，保证等宽、翻转与编辑时不跳动。

### 4.3 动效

| 场景 | 表现 |
|---|---|
| 键盘按键 | 按下 `scale(0.94)` + 底色转浅黄（180ms 轻回弹曲线） |
| 分类选中 | 图标底转主黄渐变 + 金色描边环 + `scale(1.06)` |
| 分类按下 | 图标 `scale(0.92)` |
| 主按钮 | 按下 `scale(0.985)` + 透明度 0.9 |
| 编辑弹层 | 底部上滑 240ms + 遮罩淡入 200ms |
| 空状态吉祥物 | 2.8s 循环上下浮动 8% |

统一缓动 `--cd-ease: cubic-bezier(0.34, 1.35, 0.64, 1)`（略带回弹，呼应软萌）。
`App.vue` 里已加 `@media (prefers-reduced-motion: reduce)` 全局降级，尊重系统"减弱动态效果"。

## 9. 附：形象中心（真实素材 Demo）

`demo/nailong-gallery.html` —— 一个把「奶龙」**真实图片素材**嵌进 UI 的独立设计稿，用来验证
"带图片的信息型界面"的布局、按钮层级与加载体验。它**不属于 App 发布路径**（`src/` 未改动一行）。

### 9.1 版权前置约束

- 「奶龙」版权归第七印象文化传媒（深圳）有限公司，素材取自萌娘共享。
- 仅限本机原型验证与个人学习，**不得商用/公开发布/再分发**。
- 因此 **图片文件不入库**（`.gitignore` 已排除），运行 `demo/assets/nailong/fetch.py` 本地生成。
- 要正式上线，必须换成自有/已授权素材，或直接用项目自带的原创吉祥物 `src/components/mascot/`。
- 界面底部常驻「素材说明」卡片，把来源与限制写在用户看得到的地方。

### 9.2 布局与栅格

```
┌─ 顶栏（品牌黄，标题 + 主题标签）────────────┐
│ Hero 当前形象    236px 高，图 + 名称 + 描述 + 使用中徽章 │
│ ─ 分区标题「选一个形象」 + 计数 ─             │
│ 网格 2 列 · 间距 12 · 卡片 3:4 图 + 名称        │
│ ─ 文字按钮「恢复默认形象」─                  │
│ 素材说明卡片                                │
└─ 吸底操作栏（次按钮 + 主按钮）──────────────┘
```

- 单列 430px 上限，左右统一 20px 安全边距；纵向节奏 = 16 / 22 / 12px。
- 网格用 `aspect-ratio: 3/4` 锁死卡片比例，**图片未加载时也不会跳版**。
- 选中的唯一标识是"金色描边环 + 右上角勾"，不改变盒子尺寸（用 `box-shadow` 画环），因此不会引起重排。

### 9.3 两类素材两种处理（关键）

素材实测分两类，用同一套展示方式必然有一类难看，所以按类分流：

| 类型 | 特征 | 处理 | 底 |
|---|---|---|---|
| `cutout` 白底角色图（4 张） | 外圈 99%+ 纯白 | `fetch.py` 从四边**泛洪抠白底**成透明通道；`contain` + 12px 留白 | 柔和底色（贴纸感） |
| `poster` 满幅海报（5 张） | 边缘为天空蓝等彩色 | 保留原背景；`contain`（海报本身即 3:4，等价满铺不裁切） | **取画面边缘色**，无缝衔接 |

抠图只从四边泛洪，所以角色**内部的白色高光/肚皮不会被误伤**；紧贴边缘的一圈近白像素按白度递减 alpha，消除白边。

### 9.4 按钮交互逻辑（三级）

| 层级 | 控件 | 行为 | 状态 |
|---|---|---|---|
| 主 | 设为我的形象 | 写入 `localStorage`，Toast，Hero 出现「使用中」徽章 | 已应用 → 变「✓ 已应用」+ 薄荷底 + 禁用 |
| 次 | 查看大图 | 打开灯箱预览**当前选中**项 | 始终可用 |
| 弱 | 恢复默认形象 | 清掉存储、选中与已应用回到第 1 项 | 常驻文字按钮 |
| 内容 | 网格卡片 | 点选即改 `state.selected` → Hero 与按钮态同步 | `aria-pressed` 表达选中 |
| 模态 | 灯箱 | 左右箭头 / 圆点 / Esc / ←→ / 横向滑动（>45px） | 点遮罩或 ✕ 关闭 |

单向数据流：UI 只由 `state.selected` / `state.applied` 渲染；`syncSelection()` 只改属性、**不重建网格**，
所以已加载的图片不会被丢掉，点选手感是"跟手"的。

### 9.5 图片加载策略

1. 网格只加载 `<slug>-thumb.webp`（单张 5–24KB），带 `loading="lazy"` + `decoding="async"`。
2. 先挂**半透明白色微光骨架屏**（在浅奶黄与天蓝海报上都成立），`onload` 后淡入缩放到位。
3. 失败显示占位与 `fetch.py` 提示，而不是破图——**素材缺失时界面依然完整可用**。
4. 灯箱**先秒出已缓存的缩略图**，再后台加载大图，完成后淡入替换；并发用序号令牌防抖，快速连点不会串图。
5. 大图只在打开灯箱时请求，首屏不付这个代价。

## 10. 吸顶导航：半透明 + 毛玻璃，以及它的降级链

适用文件：`demo/nailong-gallery.html` 的 `.app-bar`（顶栏）与 `.actionbar`（吸底操作栏）。

### 10.1 先决条件：顶栏必须真的"吸顶"

原实现的 `.app-bar` 是 flex 布局里的普通一项，内容在独立滚动区里滚动，**永远不会从它下面经过**——
这种情况下做毛玻璃毫无意义。所以第一步是把顶栏改成覆盖式：
`position: absolute` + 滚动区 `padding-top: var(--bar-h)`，内容因此会从顶栏下方穿过，毛玻璃才有作用对象。

### 10.2 两档渲染，默认走保守档

| 档位 | 触发 | 顶栏 | 底栏 |
|---|---|---|---|
| **纯色（默认）** | 初始状态、以及所有降级路径的终点 | `var(--bar-solid)` 不透明 | `var(--foot-solid)` 不透明 |
| **毛玻璃** | JS 判定"支持 && 系统允许 && 实测帧率够用" | `rgba(...,0.72)` + `blur(12px)` | 同左 |

**默认渲染成纯色**是刻意的架构选择：CSS 里写的是安全档，由 JS 去"加能力"。
这样 JS 未执行 / 被禁用 / 抛错时，界面只会更清楚，不会出现半透明底色漏白。
两档共用一个开关 `.app.blur-ok`，**顶栏与底栏一起切**，避免"只降一半"。

### 10.3 文字可读性：把"不透明度下限"算出来

半透明顶栏最大的风险是文字对比度随下方内容变化。做法是**先算下限，再定透明度**。

设顶栏底色亮度 `L_bar`、文字亮度 `L_text`、下方内容亮度 `L_under`、不透明度 `α`，
则合成后亮度 `L = α·L_bar + (1-α)·L_under`，要求 `(L+0.05)/(L_text+0.05) ≥ 4.5`。

**浅色档**（底色品牌黄 `#ffd34d`，`L≈0.683`；文字 `#4a3520`，`L≈0.041`）
最坏情况是下方为纯黑（`L_under=0`）：解得 **α ≥ 0.527**。取 α=0.72 有很大余量。

**深色档**（底色 `#241d15`，`L≈0.013`；文字 `#f4ead8`，`L≈0.831`）
最坏情况是下方为纯白（`L_under=1`）：解得 **α ≥ 0.866**——"半透明"几乎被算没了。
这里用另一个手段解决：`backdrop-filter` 里的 **`brightness(0.5)`**，它先把下方的亮图压暗再合成。
压暗后 `L_under≈0.216`，同样的 4.5 门槛下 **α ≥ 0.49** 即可，于是深色档取 α=0.62 也安全。

> 结论：**深色模式的半透明顶栏必须配合 `brightness()` 使用**，否则要么文字不可读，要么只能做成近似不透明。

### 10.4 降级链（全部走同一个开关）

| # | 触发条件 | 结果 |
|---|---|---|
| 1 | `CSS.supports('backdrop-filter','blur(1px)')` 为假，或 `prefers-reduced-transparency: reduce` | 直接纯色 |
| 2 | `hardwareConcurrency ≤ 2` 或 `deviceMemory ≤ 2` | 初判纯色（阈值取很保守，不误伤中端机） |
| 3 | 首次滚动时实测 p75 帧间隔 > 28ms（≈36fps） | 自动降为纯色 + 一次性 Toast 说明 |
| 4 | 降级结论写入 `localStorage`，下次直接进纯色 | 不必每次重受一遍罪 |
| 5 | 浮层（灯箱）打开 | 两条栏暂停毛玻璃 |

第 3 条是**在用户真实滚动时采样**的：静态页面测不出滚动合成的开销。
取 **p75 而非平均值**，避免一次偶发卡顿就把整机判成低端。

### 10.5 多层浮层

灯箱打开时给 `.app` 加 `has-modal`，暂停两条栏的 `backdrop-filter`。
两条栏已被 90% 深色遮罩完全盖住，**视觉上无法分辨**，但省掉全屏回读合成——低端机上很实在。

> ⚠️ 踩坑记录：这条"暂停"规则**必须写在两条栏的 `.blur-ok` 规则之后**。
> 同为 3 个类的选择器，同权重下靠后者生效；写在前面会被后面的规则盖掉，
> 表现为"顶栏停了、底栏还在模糊"的半吊子降级。已由计算样式实测抓出并修复。

### 10.6 深色模式

顶栏与底栏的深色适配不是一个特例，而是顺带完成了整套深色主题：

- 主题只由 `<html data-theme>` 一个开关驱动（JS 默认跟随系统，`?theme=dark|light` 可强制），
  **不写 `@media (prefers-color-scheme)`**，避免"媒体查询 + 属性"两套值各维护一遍。
- 新增 `--cd-on-accent`（叠在品牌黄上的字）。**这是深色模式最容易翻车的地方**：
  主按钮原本用 `--cd-ink`，深色下它会变成浅色，压到亮黄上对比度崩到约 1.5:1。
  凡"亮黄底 + 文字"的地方一律改用 `--cd-on-accent`。
- 卡片底色是按素材算出来的，换主题必须**重算**：浅色 tint 直接搬到深色下会刺眼，
  因此深色时把原色向深底混合（保留色相、压暗明度）。

### 10.7 实测结果

**文字对比度**（从渲染结果取样计算，内容滚至顶栏下方的最坏情况）：

| 主题 · 档位 | 文字色 | 顶栏实测底色 | 对比度 |
|---|---|---|---|
| 浅色 · 毛玻璃 | `(74,53,31)` | `(227,204,115)` | **7.22:1** |
| 浅色 · 纯色 | `(74,53,32)` | `(255,211,77)` | **8.06:1** |
| 深色 · 毛玻璃 | `(244,234,216)` | `(43,35,29)` | **12.94:1** |
| 深色 · 纯色 | `(244,234,216)` | `(36,29,21)` | **13.96:1** |

四档全部 ≥ 7:1，远超 AA 正文 4.5:1。

**两档是否真的不同**（同一点位，顶栏后方换成亮/暗内容）：

| 档位 | 亮背景下的顶栏 | 暗背景下的顶栏 | 最大通道差 |
|---|---|---|---|
| 纯色 | `(255,211,77)` | `(255,211,77)` | **0** → 不透明 |
| 毛玻璃 | `(255,221,119)` | `(204,202,123)` | **51** → 半透明生效 |

**运行时计算样式**（`--dump-dom` 读取）：

```

深色/浮层开启 | bar=none | foot=none
浅色/纯色(回退) | bar=none | foot=none | barBg=rgb(255,211,77)   ← alpha=1，确实不透明

```

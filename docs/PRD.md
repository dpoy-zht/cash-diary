## 1. 产品概述

### 1.1 一句话定义
一款"3 秒记一笔、随时看得清、数据不丢"的个人记账 App，先跑通 Android 单机版。

### 1.2 背景与动机
日常消费分散在扫码、外卖、交通等各种场景，事后很难回答"钱花哪了"。现有记账工具要么功能臃肿、要么强制注册登录，违背"随手记"的初心。本产品从最小闭环做起。

### 1.3 目标用户
-  primary：个人用户单机使用（开发者自用起步）
-  暂不覆盖：多人协作、家庭共享账本

### 1.4 核心价值主张
| 价值 | 含义 | 衡量方式 |
|---|---|---|
| 快 | 打开到记完 ≤ 3 步 / 3 秒 | 记账操作计时 |
| 稳 | 离线可用、数据不丢 | 杀进程重开数据完好 |
| 清楚 | 流水一目了然、改错容易 | 列表信息完备、编辑路径 ≤ 2 步 |

## 2. 产品原则

1. **闭环优先**：只做服务"记一笔 → 看得到 → 不丢"这条闭环的功能，其余一律后置。
2. **离线优先**：本地数据库是唯一事实源；没有网络也要能记账、看账。
3. **数据铁律**：金额用整数分存储；时间存毫秒时间戳；删除为软删除（详见 PLAN.md §3.3）。
4. **克制**：分类、字段、按钮能少则少；不为"以后可能用得上"提前设计。

## 3. MVP 功能范围（已冻结）

### 3.1 功能清单

| # | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| F1 | 快速记账 | 数字键盘 + 收支切换 + 分类选择 + 备注（可空）+ 日期（默认今天） | 3 步内完成一笔 |
| F2 | 内置分类 | 8 个支出类 + 4 个收入类，带图标，启动初始化 | 不建分类管理界面 |
| F3 | 流水列表 | 按时间倒序、按天分组；按月查看，月头显示当月收支合计 |  grouping 正确 |
| F4 | 编辑 / 删除 | 点击条目弹出编辑层：改金额、分类、备注；可删除（二次确认） | 改删后列表与合计即时联动 |
| F5 | 本地持久化 | SQLite 存储（Demo 阶段以浏览器 localStorage 模拟） | 杀进程数据不丢 |

### 3.2 非目标（MVP 明确不做）

| 不做 | 原因 | 归属阶段 |
|---|---|---|
| 统计图表（饼图/趋势） | 不服务核心闭环；依赖稳定数据层 | P1 |
| 预算与超支提醒 | 依赖统计能力 | P1 |
| 分类管理（增删改排序） | 内置分类已够用 | P1 |
| 多账本、搜索、筛选 | 数据量小，用不上 | P2 |
| 云同步、账号登录 | 高风险区，后置 | P3/P4 |
| 深色模式、换肤 | 打磨项 | P2 |

## 4. 信息架构

```
现金日记
├── 记一笔（默认首页）
│   └── 收支切换 / 金额键盘 / 分类宫格 / 备注+日期 / 完成
├── 明细
│   └── 月份切换 / 当月收支合计 / 按天分组的流水列表
│   └── 点击条目 → 编辑弹层（改金额/分类/备注、删除）
└── 我的
    └── 占位入口：分类管理(P1)、预算提醒(P1)、数据备份(P2)、关于
```

底部 Tab 三栏：记一笔 / 明细 / 我的。

## 5. 核心流程

### 5.1 记账流程（主流程）
```
打开 App(默认在"记一笔")
 → 选择收支类型（默认支出）
 → 键盘输入金额（必填 > 0）
 → 点选分类（必填）
 → （可选）填备注、改日期
 → 点"完成" → 落库 → Toast 提示"已记一笔"
 → 停留在本页，清空金额与备注，保留类型与分类（便于连续记账）
```

### 5.2 查看 / 编辑 / 删除流程
```
进入"明细" → 默认当月 → 可左右切换月份
 → 点击条目 → 底部弹出编辑层
 → 修改金额/分类/备注 → 保存 → 列表与月合计即时更新
 → 或点删除 → 二次确认 → 软删除 → 列表即时更新
```

### 5.3 异常与边界
| 场景 | 处理 |
|---|---|
| 金额为 0 或未选分类 | "完成"按钮禁用 |
| 删除操作 | 二次确认，防误触 |
| 某月无记录 | 空状态文案引导去记账 |
| 备注含特殊字符 | 转义后存储与展示 |

## 6. 页面详细说明

### 6.1 记一笔
| 元素 | 类型 | 规则 |
|---|---|---|
| 收支切换 | 分段控件 | 默认"支出"；切换后分类宫格随之切换，已选分类失效需重选 |
| 金额显示 | 大字右对齐 | 实时跟随键盘输入，千分位展示 |
| 数字键盘 | 3×4 宫格 | 0-9、小数点、退格；整数位 ≤ 9 位，小数位 ≤ 2 位 |
| 分类宫格 | 4 列图标宫格 | 显示当前收支类型的分类；选中高亮 |
| 备注/日期 | 输入行 | 备注可空；日期默认今天 |
| 完成 | 主按钮 | 金额>0 且已选分类才可点；点击后保留类型与分类便于连续记账 |

### 6.2 明细
| 元素 | 规则 |
|---|---|
| 月份栏 | "‹ 2026年9月 ›" 左右切换 |
| 月合计 | 支出红色总额、收入绿色总额（中国习惯：红支绿收） |
| 列表 | 按天分组（今天/昨天/M月D日 周X），组内按时间倒序 |
| 条目 | 分类图标 + 名称 + 备注（可空）+ 金额（带符号 ¥，支出 -、收入 +） |

### 6.3 编辑弹层（底部抽屉）
- 展示：类型（只读）、金额输入框、分类横排选择、备注输入框
- 操作：保存（校验金额>0、已选分类）、删除（二次确认）
- 日期不可改（MVP 范围外）

### 6.4 我的
- 仅占位入口（标记 P1/P2 敬请期待），含"重置演示数据"与版本信息

## 7. 数据模型（MVP）

```sql
category(id, name, type, icon, sort)          -- 内置，启动初始化
transaction_record(id, category_id, type, amount_cents,
                   note, occurred_at, created_at, updated_at, deleted_at)
```

- 金额一律整数分；时间一律毫秒时间戳
- `account`/`budget` 表不建（MVP 单账本、无预算）

## 8. 设计规范（v1.1 · 奶龙风暖黄治愈系）

> v1.1（2026-09-25）将整体视觉风格调整为暖黄治愈系（贴近"奶龙"的风格语言：明亮暖黄、极圆润、圆眼 + 腮红的可爱角色感）。
> 完整令牌表、对比度实测与一致性规则见 **`docs/nailong-ui-spec.md`**。
> **语义色（红支绿收）未变**，仍为下列冻结值。

| 项 | 规则 |
|---|---|
| 金额颜色 | 支出 #E24B4A（红），收入 #12924F（绿）——中国习惯 |
| 金额格式 | 千分位 + 两位小数，如 ¥1,800.00 |
| 主色（品牌） | 品牌黄 #FFD34D；主按钮与选中态用渐变 `#FFE98F → #FFC93C`，配深棕文字 |
| 顶部导航 | **自绘吸顶**（`navigationStyle: custom`）：默认不透明品牌黄；判定通过后启用半透明 + 毛玻璃；不支持或性能不足时自动回退纯色（详见视觉规范 §11） |
| 页面底色 | 奶油底 #FFF8E7；内容承载在纯白圆角卡片上 |
| 文字颜色 | 主文字 #4A3520（暖深棕，替代纯黑）；次要 #7E6849；弱化 #B9A88F |
| 圆角 | 胶囊 999px｜卡片 28px｜按钮与输入框 20px｜键盘键 16px；界面内不出现直角 |
| 字体 | 系统圆体栈（MiSans / HarmonyOS Sans / PingFang SC），不打包字体；标题与金额一律 700 |
| 金额字号 | 一律 ≥19px 粗体（语义色在"大字号"档才满足 WCAG AA；详见视觉规范 §3.3） |
| 吉祥物 | 原创「小记龙」纯 CSS 绘制，仅用于氛围点缀，不承载信息 |
| 动效 | 按下回弹 180ms；弹层上滑 240ms；已适配"减弱动态效果"系统设置 |
| 危险操作 | 删除必须二次确认 |
| 反馈 | 操作结果 Toast 提示，不打扰流程 |
| 无障碍 | 对比度按 WCAG AA 实测（正文 ≥4.5:1）；点按目标 ≥44px |

## 9. 验收标准（MVP 毕业线）

1. 打开 App 到记完一笔 ≤ 3 步
2. 连续记 10 笔，杀进程重开，数据一条不少
3. 编辑金额/分类/备注、删除流水后，列表与月合计即时正确
4. 明细按月分组清晰，月合计与明细加总一致（分毫不差——整数分校验）
5. 断网情况下以上全部可用

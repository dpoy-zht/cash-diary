# 奶龙图片素材清单（供批量替换用）

> 扫描时间：2026-10-01 ｜ 项目：奶龙记账 / cash-diary
> 扫描范围：全项目（排除 node_modules / .git / dist/build），共找到 **176 个图片文件**，
> 其中 **82 个是素材**，其余 94 个是验证截图（`dist/dev`、`dist/preview`、`dist/shots`，见 §8，不属于素材）。
> 82 个素材文件按内容去重后实际只有 **51 张不同的图**；**53 个文件卷入重复**（21 组），其中 **31 个是纯冗余副本**。

## 0. 一句话结论（先看这里）

| 你要换图时，真正需要动的只有两处 | 其它全是副本或原型参考 |
|---|---|
| **`src/static/milo/*.webp`（9 个）** —— App 运行时真正加载的图 | `dist/cache/wgt/...`、`dist/dev/app-plus/...` 是构建时从 src 复制过去的，**重新构建会自动跟随**，不用手动换 |
| **`unpackage/res/icons/`（4 个）+ 1024 母版** —— 桌面图标 | `demo/assets/` 是设计基准原型与表情包素材，**不在 App 包里**，只影响原型预览 |

⚠️ **两个必须注意的点**
1. `src/static/milo/*.webp`（9 个）**已入库 git**，但它们是「奶龙 = 第七印象商业 IP」的素材 —— 现在个人自用没问题，**上架/公开分发前必须换成有授权的图**（`.gitignore` 第 98-102 行的注释也是这个意思）。
2. `unpackage/res/icons/` 被 `src/manifest.json` 引用，但整个 `unpackage/` 目录 **被 gitignore、不入库** —— 换电脑克隆仓库后云打包会缺图标。换图标时建议把 4 个图标挪到入库目录（如 `src/static/icons/`）并同步改 manifest。

- 4 个尺寸档即 Android 各密度的启动图标，内容应与 1024 母版同图（按尺寸推断，建议替换时一并核对）。

- 记忆里的坑再提醒一次：改过 icons 后必须重新**云打包**；`distribute.icons.{android}` 层级不能挂错，挂错会被**静默忽略**（连续 3 个包都是默认 H 图标的教训）。

## 7. 同角色不同尺寸 / 格式的变体

### 7.1 milo 系列：PNG 原图（demo）→ WebP 应用图（src）
同一角色同一姿势，**格式转换 + 长边归一化到 480**：

| 角色 | demo PNG（原图） | src WebP（应用） | 变化 |
|---|---|---|---|
| milo | 854×1269, 369 KB | 323×480, 16 KB | 缩到长边 480，体积 −96% |
| milo-happy | 800×800, 46 KB | 480×480, 15 KB | 缩放 + 转格式 |
| milo-innocent | 800×800, 52 KB | 480×480, 18 KB | 同上 |
| milo-rich | 1200×1200, 439 KB | 480×480, 47 KB | 缩放幅度最大 |
| milo-jump | 474×792, 38 KB | 287×480, 15 KB | 等比缩放 |
| milo-sad | 1280×720, 72 KB | 480×270, 7 KB | 等比缩放（16:9 保持） |
| milo-caishen | 520×520, 28 KB | 480×480, 20 KB | 轻微缩放 |
| milo-gold | 393×393, 19 KB | 393×393, 15 KB | **只转格式未缩放** |
| milo-waving | 400×469, 132 KB | 400×469, 11 KB | **只转格式未缩放**（体积 −92%） |

> 结论：**替换时给一张长边 ≥480 的透明底图即可**，App 端会按 CSS 显示尺寸渲染；
> 若想严格复刻现状，就按"长边 480、WebP 有损、透明通道"处理。

### 7.2 nailong 表情包：`-full` vs `-thumb`
同一张图的两档尺寸（§4 表），thumb 统一长边 420，供画廊列表用；full 供大图预览。

### 7.3 应用图标：4 档密度 + 1024 母版
72 / 96 / 144 / 192 / 1024（见 §2）。

## 9. 批量替换操作清单（建议顺序）

1. **准备**：9 张透明底新图（对应 §1 的 9 个角色/姿势）+ 1 张 1024×1024 图标母版。
2. **替换 App 素材**：覆盖 `src/static/milo/` 的 9 个 `.webp`（保持**文件名不变**就不用改任何代码）。
   - 用 `cwebp -q 80` 或 Pillow 转换；逐个核对 `milo-sad` 保持 16:9 横幅构图。
3. **替换图标**：由 1024 母版缩出 72/96/144/192 覆盖 `unpackage/res/icons/` 四个文件；
   （可选）把 4 个图标挪进 git 跟踪目录并改 `src/manifest.json`，消除"克隆后打包缺图标"的风险。
4. **原型同步**（可选）：同名覆盖 `demo/assets/milo/*.png`。
5. **清理**：删 `dist/_raw_nailong/look-big-dragon.jpg`（存错扩展名的网页）；`dist/` 其余副本无需手动处理。
6. **验证**：
   - `rm -rf dist/build/app && npm run build:app`，确认 `dist/build/app/static/milo/` 已是新图；
   - 真机装调试基座 → 推 www → 逐页截图核对（首页/统计/记一笔/账本/我的 + 三个弹窗/空态）；
   - **换图标必须重新云打包**（wgt 热更不含图标），发版前核对 APK 内 `res/` 图标已更新。
7. **合规**：新素材确认授权范围后再提交；当前 9 个奶龙 webp 在 git 里，替换 commit 时顺带在 README 注明素材来源与授权。

# 账本页「菜单」功能分析与建议

> 分析时间：2026-10-06 ｜ 对应需求第 4 项
> **结论先说：值得做，但不该做成"菜单"。推荐改为「账本设置」，且只放 2~3 项。**

---

## 1. 这个菜单按钮现在是什么

`src/pages/ledger/ledger.vue:5` 有一个 navbar 左侧的菜单图标按钮，点击弹
toast「菜单功能规划中」—— 即**占位桩，从未定义过任何功能**。

而同一行右侧是「新建账本」（`onCreate`，已实现）。所以现状是：
导航栏左边挂着一个**没有行为的按钮**，比没有更糟 —— 用户会点，点完只得到一句
"规划中"。

---

## 2. 账本页实际缺什么（盘出来的能力缺口）

| 现状 | 账本页已有 | 缺什么 |
|---|---|---|
| ✅ 当前账本卡（余额、已存/已花） | ✅ 点一行切换账本 | ❌ **账本无排序**（新建的在最上，余额大的排哪全看创建顺序） |
| ✅ 其他账本列表 + 圆点色标 | ✅ 长按改名/删除 | ❌ **账本无图标/备注** |
| ✅ 空态插画 | ✅ 新建账本 | ❌ 无「当前账本改名/删除」的显式入口（要长按其他账本才行，**当前账本长按不了**） |

**顺带查了「我的」页已有 12 项**（预算/固定支出/分类/标签/备份/WebDAV/体检/
更新/超支提醒/每日提醒/音效/关于）—— 菜单**绝不能放这些的入口**，否则是重复入口。

---

## 3. 是否值得规划

### 值得做的理由

1. **有一个真实且明显的缺口**：当前账本不能改名、不能删除。别的账本要"长按"才
   能操作，而**当前账本长按没反应**（长按逻辑绑在"其他账本"那一行上）。
   这不是"锦上添花"，是**能力不完整**。
2. **位置合适**：账本页就是账本的操作中心，账本相关设置放这里符合直觉。
3. **成本可控**：排序与图标都是小改动，不需要新页面。

### 不宜做太多的理由

- 记账 App 的账本功能**天然简单**（建、切换、改名、删），硬凑菜单会让简单的事变复杂
- 项目已定版（README 明确写"功能定版，不再新增功能"）→ **新增功能需先审批**
- 排序/图标这类功能**收益递减**：3 个账本时无所谓，10 个才有意义，而实际用起来
  一般不超过 5 个

---

## 4. 推荐方案

### 定位：**「账本设置」**（不叫"菜单"）

理由：叫"菜单"会让人预期是导航（去别的页），但这里做的是**当前账本的操作**，
叫"设置"更准确。而且做成**底部弹层**（复用既有的 sheet 组件），不是跳转页。

### 入口位置：**保留 navbar 左侧按钮**

- 右侧已是"新建"，左侧放"当前账本的操作"，职责清晰、左右分工明确
- 底部弹层比跳转页更轻 —— 改个名不用离开当前上下文

### 建议的菜单项结构（**3 项，克制**）

| 项 | 行为 | 为什么值得做 |
|---|---|---|
| **重命名当前账本** | 复用已有 `renameLedger()` | **补真实缺口**：现在改不了当前账本的名字 |
| **删除当前账本** | 复用 `removeLedger()` + 已有删除确认弹窗 | 同上。删当前账本需二次确认（会切回默认账本） |
| **账本排序** | 按"最近使用"或"余额"排；只改内存里的展示顺序，不动数据 | 让常用账本排前面，是真实需求 |

### 明确**不做**的（避免把菜单做成功能仓库）

| 项 | 为什么不做 |
|---|---|
| 账本图标/封面 | 要新增素材与上传逻辑，收益低；现有圆点色标已够区分 |
| 账本预算独立设置 | 「我的 → 预算设置」已有，重复入口 |
| 账本备注/描述 | 极少人写，属于"为了完整而完整" |
| 导入/导出单账本 | 备份恢复是全局功能，不要按账本拆开 |

## 5. 若要实施，落点清单（供参考，尚未动代码）

```
src/pages/ledger/ledger.vue
  ├─ 模板：把 navbar 左按钮的 toast 改成打开底部弹层
  ├─ 复用 components/edit-sheet（已有改名弹层，含输入框与校验）
  ├─ 复用 components/confirm（删除确认，参考 removeLedger 现有实现）
  └─ 排序：新增一个 computed 排 others，**不改数据库**（展示层排序）
```

**风险提示**：删除当前账本要处理"删完切到哪个"的边界（现有 `removeLedger`
是删非当前账本的路径，当前账本这条分支需要补）。

---

## 6. 建议的决策

| 选项 | 说明 |
|---|---|
| **A（推荐）** | 做「重命名 + 删除当前账本」两项 —— 补真实缺口，成本低、风险小 |
| B | A + 排序（共 3 项）—— 也可以，但排序的实际收益随账本数量递减 |
| C | 不做，把 navbar 左按钮**直接删掉** —— 每行少一个假入口，账本页靠长按操作 |
| D | 做完整菜单（图标/备注/排序/预算）—— **不建议**，超出定版范围 |

**我的建议是 A**：先补上「当前账本不能改名/删除」这个真实缺陷。
若你觉得连这个也不算常用，选 C（删按钮）也完全成立 —— 一个点了没反应的按钮，
删掉比留着更好。

> 需要你拍板选 A / B / C，AI 侧不擅自扩大功能范围（README 定的规矩：新增功能先审批）。

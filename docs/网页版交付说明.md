## 一、结论先行

**这个项目本来就是「一套代码 + 双端产物」的架构，网页版不需要重写。**

- uni-app（Vue 3 + Vite）原生支持 `npm run build:h5`，`package.json` 里这条脚本一直存在。
- 数据层做了「双适配器」：App 端走 `plus.sqlite`，非 App 环境走 `db/memory.js`，
  由 `db/index.js` 按 `typeof plus !== 'undefined'` 自动路由。
- **`db/memory.js` 早就直接读写 `localStorage`**（key `cashDiary.memory.v1`），
  带 200ms 防抖合并写、配额超限错误上报、事务快照回滚。
  所以「刷新后数据保留」这条要求，**代码里已经实现，不是本次新加的**。

实测证据：用真实 UI（点 + → 数字键盘输 25.50 → 完成）记一笔，
然后**关掉整个浏览器进程、重新打开**，同一 profile 下账目仍在：
`amount_cents = 2550`（整数分）、首页正确渲染出「今天 10月24日 周六 支出 ¥25.50 餐饮」。

真正需要动的只有一件事：**桌面端布局**。

## 三、网页版方案与实现

### 3.1 设计取舍：为什么用「居中画布」而不是「重排两栏」

记账 App 的信息密度是围绕单列手机屏设计的（余额卡 → 搜索 → 分段 → 按日分组的流水）。
硬拆成两栏要重写 11 个页面的布局，风险和收益不成比例。

最终选择：**窄屏保持原样全屏，宽屏收成一块居中的「应用画布」**。

- 分界线 `@media (min-width: 560px)`
- 画布宽 520px，圆角 26px，带阴影，两侧是暖色渐变氛围底
- 移动端（< 560px）**一行 CSS 都不生效**，与原 App 表现完全一致（已截图对比确认）

### 3.2 一个属性解决 10 处 fixed

这是本次最省事也最关键的一招：

```css
uni-app {
  transform: translateZ(0);   /* 让 fixed 后代以本元素为包含块 */
  max-width: 520px;
  margin: 28px auto;
  overflow: hidden;
  border-radius: 26px;
}
```

CSS 规范里，**带 `transform` 的祖先会成为 `position: fixed` 后代的包含块**。
只加 `max-width` 是关不住底部 tab 栏和四个弹层的 —— 它们会横跨整个浏览器窗口。
加这一个属性，10 处 fixed 元素全部自动收进画布，**不用改任何组件代码**（也就碰不到 App 端）。

实测：tab 栏 `bottom` 精确落在画布 `bottom`（872/900），滚动内容时纹丝不动。

### 3.3 滚动容器的迁移

画布定高 + `overflow: hidden` 之后暴露了一个真问题：
`uni-page-body` 实测高 990px > 画布 844px，内容会被**直接裁掉而不是滚动**。

修法：把滚动交给 `uni-page-wrapper`（`overflow-y: auto`），
底部 tab 栏因为上面那个 transform 仍然固定在画布底部，不会跟着内容滚走。
实测：`scrollHeight 990 / clientHeight 844`，滚到 120 后 tab 栏仍稳在 808–872。

### 3.4 桌面交互细节

- **手型光标**：选择器不是拍脑袋写的 —— 用脚本解析 `src` 下所有带
  `@click` / `@tap` / `hover-class` 的元素，提取出 **60 个 class** 再人工排除
  `mask` / `tc-mask` 这类遮罩
- **hover 反馈**：`filter: brightness(0.96)`，不用 `transform`（避免和组件自己的过渡动画打架）
- **焦点环**：输入框 `:focus-within` 加黄色外发光，键盘 Tab 走查时看得见落点
- **允许选中文字**：`user-select: text`（移动端习惯是禁选，网页里反而不方便复制金额/备注）
- 全部包在 `@media (hover: hover) and (pointer: fine)` 里，触屏设备不会粘住 hover 态

### 3.5 示例数据（H5 专属）

首次打开是空库，只能看到空状态。空状态里加了一个「**载入示例账目**」按钮，
一键灌入 9 笔模拟数据（早餐/午餐/奶茶/公交/火锅/外套/外卖/房租/工资）。

**关键：走 `txStore.add` 而不是直接写 localStorage。**
直接改存储会绕过金额校验、账本归属、月分桶，造出来的数据"看起来对、一操作就露馅"。
走 store API 等于和用户手点记账**完全同一条链路**，金额同为整数分、软删字段同样齐。

### 3.6 「原 App 不动」的验证

这是硬要求，所以做了逐文件指纹比对（对照改造前的发布版构建）：

| 文件 | 结果 |
|---|---|
| `app.css` | sha256 **完全一致** |
| `app-config.js` | 完全一致 |
| `app-config-service.js` | 完全一致 |
| `__uniappview.html` | 完全一致 |
| `manifest.json` | 完全一致 |
| `app-service.js` | **字节数完全相同（353737）**，仅 1 处差异 |
| 文件总数 | 同为 48 |

`app-service.js` 的唯一差异是 home.vue 的 Vue scoped 哈希
`data-v-fddb8e98` → `data-v-7b263799`（由文件内容哈希自动生成）。
该哈希在 JS 与 `pages/home/home.css` 两侧自洽，**归一化后 home.css 逐字节相同**，
不影响任何表现。

网页版痕迹在 App 产物里 **0 命中**：
`demo-seed`、`载入示例账目`、`seedDemoData`、`onSeedDemo`、`min-width: 560px`。

手段：`src/main.js` 里用 `// #ifdef H5` 条件编译引入 `styles/h5-shell.css`，
home.vue 的入口用 `<!-- #ifdef H5 -->` 包住 —— App 构建时整段被剔除。

## 四、启动与部署

### 4.1 本地开发

```bash
npm install
npm run dev:h5          # 开发服务器，改代码热更新
```

### 4.2 生产构建 + 本地预览

```bash
npm run build:h5        # 产出 dist/build/h5，约 1.1 MB
python -m http.server 8080 --directory dist/build/h5
# 浏览器打开 http://localhost:8080
```

> `--directory` 参数很关键：如果直接 `cd dist/build/h5` 再起服务，
> 目录会被进程占住，后续重新构建时 `mv` 会报 `Device or resource busy`。

### 4.3 部署到公网

产物是**纯静态**（`index.html` + `assets/` + `static/`），任何静态托管都能上：

**方案 A：托管平台（已采用）**

已通过 WorkBuddy 应用发布部署：
https://naiwa-ledger.app.workbuddy.host/?sharecode=HKSDNKLVIM

**方案 B：自有服务器（Nginx）**

```bash
npm run build:h5
scp -r dist/build/h5/* root@<你的服务器>:/var/www/naiwa-web/
```

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/naiwa-web;
    index index.html;

    # uni-app H5 用 hash 路由，刷新深层路径要回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
    # 静态资源长缓存（文件名带内容哈希）
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

**方案 C：GitHub Pages**

```bash
npm run build:h5
npx gh-pages -d dist/build/h5
```

> ⚠️ 注意：uni-app H5 默认使用 **hash 路由**（`#/pages/home/home`），
> 所以 `try_files` 回退其实用不上，但加上无害。
> 如果将来改成 history 路由，就必须要有这条回退规则。

## 七、演示与答辩值得强调的技术点

### 7.1 「一个属性关住 10 处 fixed」——最出彩的一条

**问题**：页面里有 10 处 `position: fixed`（底部 tab、4 个弹层、各页 FAB）。
把 App 收成 520px 居中画布后，这些元素仍然横跨整个浏览器窗口。

**常规解法**：改 10 个组件，把 `fixed` 换成 `absolute` —— 但那会同时影响 App 端。

**实际解法**：给画布容器加 `transform: translateZ(0)`。
CSS 规范规定带 `transform` 的祖先会成为 fixed 后代的包含块，一行搞定全部 10 处。
**零组件改动，因此 App 端零风险。**

> 答辩话术：这不是 hack，是 CSS 规范里「包含块（containing block）」的正常用法，
> 只是平时很少被用来做布局约束。

### 7.2 「数据持久化早就是好的」——不要先动手写代码

接手需求时最容易犯的错：看到「网页版需要本地存储」，立刻动手写 localStorage 适配器。
实际读代码发现 `db/memory.js` 早就实现了，还带防抖合并写、配额超限上报、事务快照回滚。

> 答辩话术：先量清楚「哪些是真缺口」，再决定改什么。这次五个需求里，
> 四个是现成的，真正的缺口只有一个。

### 7.3 用「指纹比对」证明没动原 App

硬性要求是「原 App 不要改动」，但改了 home.vue 的模板，构建产物必然变。
怎么证明影响可控？

逐文件 sha256 比对 + 字节数比对 + 归一化哈希后再比对，最终定位到
**唯一差异是一个由文件内容自动生成的 scoped 样式哈希**，且 JS 与 CSS 两侧自洽。

> 答辩话术：说「我没改坏」是不够的，要给出可比对、可复现的证据。

### 7.4 条件编译做双端隔离

```js
// #ifdef H5
import './styles/h5-shell.css'
// #endif
```

```html
<!-- #ifdef H5 -->
<view class="demo-seed" @click="onSeedDemo">载入示例账目</view>
<!-- #endif -->
```

App 构建时这两段整个被剔除，产物里搜不到任何痕迹（已验证 5 个关键字 0 命中）。

### 7.5 真机 / 浏览器验证的边界

- 移动端特性（`<input>` 边框写法、`Intl` 缺失）**只能在真机暴露**，浏览器永远掩盖
- 桌面布局问题**只能在宽视口暴露**，手机上看不出来
- 所以验证必须双端双视口都跑：本次用了 1440×900 桌面 + 390×844 移动
- 自动化手段：CDP 真实鼠标事件 + 截图 + 读取 `localStorage` 断言

### 7.6 一个反直觉的细节：`<input>` 不能自己带边框

`App` 端 `<input>` 会被包一层 `uni-input`。当 `border` / `padding` / `width`
写在输入框自己身上时，外层照样照 CSS 画出边框和底色，
但**内层原生 input 被压成零尺寸** —— 字不显示、也点不动。
而占位符是独立 overlay 元素，照样显示。

「**占位符可见但值不可见**」就是这个坑的指纹。
修法：边框/内边距/底色全挪到外层包裹 `<view>`，输入框只留 `flex: 1` + 字体。

> 这个坑在网页版里复现不了（H5 没有这层包装），是 App 端专属的。

## 十、桌面两栏布局与深色主题

在「居中单列画布」之外，追加了一套**桌面专属的两栏布局**：宽屏下左列表、右统计，
深色配色，两栏独立滚动。

### 10.1 布局结构

```
表头（跨两栏，不滚动）：月份 ‹ › · 已存 · 已花 · 预算提示 · ＋记一笔
────────────────────────────┬──────────────────────
左栏：搜索 / 筛选 / 分段 / 按日分组的流水    右栏：本月概览 / 支出构成圆环 / 分类排行
         （独立滚动）                                    （独立滚动）
```

- 门槛：`@media (min-width: 1024px)`，与 JS 里的 `DESK_MIN_WIDTH = 1024` 必须对齐
- 1023px 及以下自动退回原来的单列布局（`deskMode = false`）
- 两栏用 CSS Grid：`grid-template-columns: minmax(0, 1fr) minmax(330px, 400px)`

### 10.2 四个必须做对的技术点

**① 画布要放宽**
之前的 520px 居中画布是单列手机宽度，两栏根本放不下。
用更高特异性的 `html.cd-desk uni-app { max-width: 1240px }` 覆盖。

**② 独立滚动靠 `min-height: 0`**
flex/grid 子项默认 `min-height: auto`，会被内容撑高，于是变成"整页一起滚"。
链路上每一层（`.page` → `.desk` → `.desk-body` → `.desk-pane`）都要显式设 0，
再给两栏 `overflow-y: auto`。

**③ 不许横向溢出**
grid 用 `minmax(0, 1fr)` 让左栏可压缩；所有横向子项加 `min-width: 0`；
长备注/长分类名一律 `text-overflow: ellipsis`。

**④ 底部 tab 栏会压住两栏**
`tabbar` 是 `position: fixed`（靠 `uni-app` 上的 transform 关在画布内），
它浮在两栏之上。`.page` 必须显式让出 72px，否则面板底部被切掉一条。

### 10.3 深色主题：只覆盖令牌，不覆盖组件

全站色值都走 `var(--cd-*)`，所以在 `<html>` 上加 `.cd-dark` 一处，
卡片、列表、弹层、底部栏会整体翻转 —— **不需要在任何组件里写深色特例**。

令牌在 `src/styles/theme-dark.css`：

| 用途 | 令牌 | 值 |
|---|---|---|
| 页面底 / 卡片 / 抬升 | `--cd-bg` / `--cd-surface` / `--cd-surface-2` | `#0e0b08` / `#1c1710` / `#262017` |
| 结构边线 / 密集分隔线 | `--cd-line` / `--cd-line-soft` | `#7d6e58` / `#4d4236` |
| 主文字 / 次文字 | `--cd-ink` / `--cd-ink-2` | `#f6f0e6` / `#cdbfa6` |
| 蛋黄主色 / 按钮字 | `--cd-primary` / `--cd-btn-ink` | `#ffd93d` / `#241c0c` |
| 收入 / 危险 | `--cd-income` / `--cd-danger-ink` | `#6ee7a8` / `#ff9a94` |

⚠️ **踩过的坑**：App.vue 把令牌定义在 `:root, page, uni-page-body` **三处**。
只在 `html` 上覆盖时，页面内元素仍继承 `uni-page-body` 那份浅色值，
表现为"面板还是白的，但只在深色文件里定义的新令牌却生效了"的半翻转状态。
所以选择器必须**同时覆盖这三个落点**。

### 10.4 对比度：先算再选，并落成测试

不靠肉眼判断 —— 深色底会把中灰读成"还行"，实测常常只有 2.x:1。

- `src/utils/contrast.js`：WCAG 相对亮度、对比度、CSS 令牌解析（纯函数）
- `tests/theme-dark.test.js`：**17 条断言**，改色改坏了测试会红

| 项 | 阈值 | 实测 |
|---|---|---|
| 正文 / 卡片底 | ≥ 4.5:1 | **14.6:1** |
| 次文字 / 卡片底 | ≥ 4.5:1 | **8.6:1** |
| 按钮字 / 蛋黄 | ≥ 4.5:1 | **12.2:1** |
| 收入绿 / 卡片底 | ≥ 4.5:1 | **11.0:1** |
| 危险红 / 卡片底 | ≥ 4.5:1 | **8.3:1** |
| 结构边线 / 卡片底 | ≥ 3:1（WCAG 1.4.11） | **3.6:1** |
| 密集分隔线 / 卡片底 | ≥ 1.5:1 | **1.8:1** |
| 图标 / 卡片底 | ≥ 3:1 | **10.6:1** |

测试还包含一条**完整性断言**：亮色里定义的每个界面令牌，深色都必须覆盖。
（吉祥物的 `--cd-face-*` 是固定插画，显式列入例外并注明理由 ——
深色下保持原来的暖黄形象才认得出。）

> 深色下有一个反直觉点：**蛋黄按钮上的字必须用深色**（`#241c0c`）。
> 白字压在 `#ffd93d` 上只有 **1.3:1**，完全不达标。

### 10.5 状态管理：状态不搬家

`desk-view` 是**纯展示组件**，月份 / 分段 / 搜索词 / 筛选条件 / 分组结果
全部由 `home.vue` 持有，子组件只收 props、派发事件。

好处有两个：
1. 分组、查表、汇总只有一份实现 —— 不会出现"两栏和小屏列表口径不一致"
2. 缩窄窗口退回单列时，用户选好的月份和搜索词不会丢（状态根本没动过）

### 10.6 主题开关的作用域

`.cd-dark` / `.cd-desk` 挂在 `<html>` 上（要覆盖不在 desk-view 内的底部栏与弹层），
它们会影响**所有**页面，所以必须跟着首页的可见性开关：

- `onShow` / `onMounted` → 挂上
- `onHide` / `onUnmounted` → 摘掉
- `watch(deskMode)` → 同步

否则跳到统计页会变成"1240px 宽的深色单列"，比不改更糟。
